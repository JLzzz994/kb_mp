# 研发中心内部技术规范

## 一、代码规范

### 1.1 Python

- PEP 8 + ruff 强制（line-length=100）
- 类型注解覆盖率 ≥ 80%（关键函数 100%）
- 函数 docstring 一句话说明 + 入参/返回
- 不写无用的 try/except，让异常自然抛出

### 1.2 TypeScript

- ESLint + Prettier
- 接口（interface）vs 类型别名（type）按场景区分：
  - interface 用于可扩展对象（DTO / Schema）
  - type 用于联合类型 + utility 类型

### 1.3 Git 提交

- Conventional Commits（feat / fix / docs / refactor / test）
- 一个 commit 一件事
- 提交前先 ruff + pytest 三件套绿

## 二、API 规范

- 路径：`/api/v1/<resources>`（kebab-case 复数）
- 动词：用 HTTP method 表达，不在路径里加 `/create /delete`
- 鉴权：除 login / health 外全部走 JWT
- 权限：dependencies=[Depends(require_permission("code:read"))]
- 错误：统一走 AppError + http_error_from_app_error

### 2.1 错误码约定

| HTTP | 业务码 | 含义 |
|---|---|---|
| 400 | invalid_request | 请求参数错误 |
| 401 | unauthenticated | 未登录 |
| 403 | forbidden | 无权限 |
| 404 | not_found | 资源不存在 |
| 409 | conflict | 状态冲突（如已存在） |
| 422 | business_rule_violated | 业务规则违反 |
| 500 | internal_error | 系统异常 |

## 三、数据库规范

### 3.1 命名

- 表名：小写下划线（snake_case）+ 复数（users / knowledge_units）
- 主键：统一 `id`，自增 BIGINT UNSIGNED
- 外键：`<table>_id`（如 `user_id`）
- 时间：`created_at` / `updated_at`（DATETIME，server_default=now()）
- 状态：枚举用 VARCHAR + check constraint（如 status='active'/'archived'）

### 3.2 索引

- 单列索引：高频查询 + 外键
- 复合索引：最左前缀原则，顺序按选择性高低
- 唯一索引：业务唯一字段（username / email / unit_code）
- 不要在 TEXT / MEDIUMTEXT 上建普通索引（用前缀索引 mysql_length=N）

## 四、AI 工程规范

### 4.1 Prompt

- 系统提示词与用户提示词分离
- 关键事实（角色 / 权限 / 业务规则）放在 system prompt
- 引用文档与多轮历史放在 user prompt
- 温度 0.3（事实性问题），0.7（创造性场景）

### 4.2 向量化

- 选择 embedding 模型时考虑语言（中英 vs 多语言）+ 维度 + 成本
- 向量检索 + 关键字检索混合召回
- 召回后必须做权限过滤（4 维 OR 逻辑）
- Top-K 一般 10-20，配合 rerank 精排到 3-5

### 4.3 LangGraph 节点设计

- 每个节点单一职责，便于单元测试
- 节点间用 TypedDict 传递状态，避免共享可变状态
- 中断（interrupt）必须有恢复（resume）路径
