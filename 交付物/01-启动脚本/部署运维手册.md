# kb_mp 部署运维手册

## 1. 部署架构

```
kb_mp 部署架构
─────────────────────────────────────────────────────────────
            ┌──────────────┐
            │   Vite 5173  │  (前端 dev)
            └──────┬───────┘
                   │ /api → 8000
            ┌──────▼───────┐
            │ FastAPI 8000 │  (uvicorn)
            └──────┬───────┘
                   │
        ┌──────────┼──────────┬──────────────┐
        │          │          │              │
   ┌────▼───┐ ┌────▼────┐ ┌───▼────┐ ┌──────▼─────┐
   │ MySQL  │ │  Redis  │ │ Milvus │ │  BGE-M3    │
   │  3306  │ │  6379   │ │ 19530  │ │ (本地模型) │
   └────────┘ └─────────┘ └────────┘ └────────────┘
```

## 2. 服务清单

| 服务 | 端口 | 用途 | 依赖关系 |
|------|------|------|---------|
| 前端 Vite | 5173 | 静态开发服务器 | 后端 |
| 后端 FastAPI | 8000 | API 服务 | MySQL/Redis/Milvus |
| MySQL | 3306 | 主数据存储 | 无 |
| Redis | 6379 | 鉴权位图 + FAQ 缓存 | 无 |
| Milvus | 19530 | 向量检索 | etcd + MinIO |
| etcd | 2379 | Milvus 元数据 | 无 |
| MinIO | 9000 | Milvus 对象存储 | 无 |

## 3. Docker Compose 部署

`deploy/docker-compose.yml` 一键拉起全部服务：

```bash
cd deploy
docker compose up -d
```

启动后检查：

```bash
docker compose ps
curl http://localhost:8000/api/v1/health
```

## 5. 环境变量

详见 `.env.example`，关键字段：

```ini
DATABASE_URL=mysql+aiomysql://kb_user:kb_password@localhost:3306/kb_mp
REDIS_URL=redis://localhost:6379/0
JWT_SECRET=kb-mp-demo-secret-change-me
EMBEDDING_BACKEND=local_bge        # local_bge | remote_openai
MILVUS_URL=http://localhost:19530
```

## 8. 常见问题

### Q1: 启动后 8000 端口被占用
查找：`lsof -i :8000` / `netstat -ano | findstr :8000`
解决：修改 `main.py` 的 port，或停占端口进程

### Q2: 鉴权失败（401/403）
检查 JWT_SECRET 一致性、Redis 缓存、用户 status 字段

### Q3: Milvus 连接失败
演示期可降级到 mock（`embedding_backend=mock`）；生产需 Milvus 2.5+

### Q4: AI 问答召回为空
- 检查知识权限：用户是否对 `unit` 有访问权
- 检查 Milvus 数据是否已 upsert
- 看 SSE 流中的 `unauthorized` 事件
