## 1. 项目目标与范围

### 1.1 目标
构建集 **知识维护 / 多维权限管理 / AI 鉴权问答 / 数据看板 / 知识沉淀** 五位一体的企业级知识库平台。详细业务边界见 PRD §1。

### 1.2 范围内
- 单篇与批量文档导入 → 知识单元入库 → 向量化
- 用户 / 角色 / 部门 / 操作权限 / 四维数据权限（global / department / role / user）
- AI 智能体鉴权召回 → 流式回答 → 权限缺失提示
- 数据看板：访问量 / UV / 知识热度 / Token 消耗 / 响应时间
- FAQ 自动挖掘 + 审核发布 + Redis 缓存命中 + 知识缺口识别

### 1.3 范围外
- 多租户隔离（单租户）
- 移动端原生 App
- 对外开放 API 平台
- 实时协同编辑
- 工作流审批引擎（仅 FAQ 审核这一种简单状态机）

### 3.2 依赖方向

```
HTTP API (app/api)
   ↓
Service (app/services)
   ↓
Workflow (app/workflows) ─→ Domain (app/domain)
   ↓                          ↓
Repository (app/repositories)
   ↓
Infrastructure (app/infrastructure: DB / LLM / Milvus / Redis / 解析器)
```

**模块边界规则**：
- Router 只做 HTTP 转换和依赖注入，不直查库
- Service 持有事务边界和用例编排，不写 SQL
- Workflow 节点只做业务动作 + 状态增量，不创建客户端
- Repository 不做跨用例编排
- Domain 不依赖 FastAPI / SQLAlchemy / LangChain

### 3.3 状态分离

| 状态类别 | 内容 | 存储 |
| --- | --- | --- |
| 业务状态 | query / session_id / recalled_units / authorized_units / unauthorized_units / answer / step | LangGraph State（TypedDict）+ chat_sessions 持久化 |
| 运行上下文 | LLM / Milvus Client / Redis / Repository | LangGraph `context_schema` + lifespan |
| 展示状态 | pending / running / succeeded / failed / progress | SSE Event（不进入业务状态） |

## 5. 核心业务流程

### 5.1 知识导入流程（端到端）

```
[知识管理员] 上传单/多文件（PDF/MD/DOCX/TXT）
        │
        ▼
[knowledge_import_service] 计算 SHA-256(content) 作为 content_hash
        │ 命中已存在 unit_code 则拒绝重复入（幂等）
        ▼
[知识单元] 落盘 storage/uploads/<uuid>.<ext>
        │
        ▼
[parser_factory] 按扩展名路由（Format-Handler-Map）：
        │   pdf → pypdf；docx → python-docx；md → markdown-it；txt → UTF-8 失败回退 GBK
        ▼
[splitter] 保护块占位符切片法
        │   1) extract_protected_blocks：代码块/表格/公式 → UUID 占位符
        │   2) split_by_titles：按 ^#{1,6} 粗切
        │   3) refine_chunks：超长用 RecursiveCharacterTextSplitter 细切
        │   参数：CHUNK_MAX_SIZE=1000、CHUNK_SIZE≈600、CHUNK_OVERLAP=100
        │         separators=["\n\n", "\n", "。", "！", "？"]
        │   4) 从后往前 replace 占位符回原内容
        ▼
[knowledge_unit_repository] 批量 INSERT knowledge_units
        │   每片写入一行，unit_code = KU-<yyyyMM>-<seq6>
        ▼
[BackgroundTasks.add_task] milvus_upsert(units)
        │ 失败不入业务错误，仅记日志与 status=vector_pending
        ▼
返回 202 + task_id / 或同步返回单元列表（取决于文件数）
```

### 5.2 AI 鉴权问答流程（LangGraph 8 节点）

```
[POST /api/v1/ai/chat/stream] SSE

LangGraph 拓扑：
  faq_cache_lookup ──hit──▶ generate(直接输出标准答案) ──▶ record_log ─▶ END
                  └─miss─▶ retrieve ──▶ rerank ──▶ permission_filter
                                                              ├─空集─▶ interrupt(等待用户重述) ─▶ END
                                                              └─有集─▶ assemble_prompt
                                                                         ──▶ generate
                                                                         ──▶ record_log ─▶ END
```

| 节点 | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| `faq_cache_lookup` | question, session_id | answer \| None | Redis hash key `faq:cache:<question_hash>` 命中即返回（带单元版本校验） |
| `retrieve` | question | recalled_units: list[(unit_id, score)] | Milvus 向量检索 Top-20 |
| `rerank` | recalled_units | reranked_units, cut_top_k | 动态断崖截断：score[i+1]/score[i] < 0.75 时停止；Top-K ∈ [1, 10] |
| `permission_filter` | reranked_units, user_id | authorized_units, unauthorized_units | 拉用户权限位图 → 内存 OR 集合运算；authorized 为空时触发 interrupt |
| `interrupt` | question, session_id | None | 鉴权+召回均空时挂起，回 SSE `INTERRUPT` 事件；用户重述后通过 `POST /api/v1/ai/chat/resume` 恢复 |
| `assemble_prompt` | authorized_units, question, history | prompt_messages | 系统提示 + 历史（近 6 轮，超长用 LangGraph `trim_messages` 压缩）+ 引用上下文 |
| `generate` | prompt_messages | answer, usage | LLM 流式输出，统计 Token |
| `record_log` | 全部上下文 | None | 写 `qa_access_logs`（失败不抛错） |

**鉴权接口**（AI 节点内部调用，复用同一接口供前端调用）：
```
POST /api/v1/knowledge/check-permissions
body: { user_id, unit_ids }
resp: { authorized_unit_ids: [...], unauthorized_unit_ids: [...] }
```

**鉴权算法**（内存集合运算）：
```
unit_permissions_for_user = {
    global:   set(unit_id where target_type='global'),
    dept:     set(unit_id where target_type='department' AND target_id IN user.dept_ids),
    role:     set(unit_id where target_type='role' AND target_id IN user.role_ids),
    user:     set(unit_id where target_type='user' AND target_id = user.id),
}
authorized = global ∪ dept ∪ role ∪ user
unauthorized = unit_ids - authorized
```

**FAQ 缓存版本校验**（faq_cache_lookup 节点内）：
```
cached = HGET faq:cache:<hash> { answer, related_unit_id, unit_updated_at }
if cached and knowledge_units[related_unit_id].updated_at == cached.unit_updated_at:
    return cached.answer
else:
    HDEL faq:cache:<hash>  # 失效
    return None
```

**多轮历史窗口**（assemble_prompt 节点内）：
- 最多取近 6 轮，超长用 `trim_messages` 或 LLM 摘要压缩
- `chat_sessions.history_json` 同时记录 `slots`（已确认的主体/实体）与 `pending_turn`（草稿），便于 interrupt/resume 时续接

### 5.3 FAQ 沉淀闭环

```
[APScheduler job, 每日凌晨 02:00]
        │
        ▼
[faq_mining_service]
  1) 从 qa_access_logs 拉近 30 天 question
  2) 嵌入（text-embedding-3-small）→ 内存向量
  3) 频次 ≥ 3 且余弦相似度 ≥ 0.80 视为同一类
  4) 关联同类对应的所有 recalled_unit_ids（取众数 Top-3）
  5) 调用 LLM 草拟 standard_answer
  6) INSERT faqs (status='pending_review', source_type='auto_mined')
        │
        ▼
[知识管理员] 审核页：approve（可编辑标准答案） / reject
        │
        ▼ approve
[faq_review_service]  UPDATE faqs SET status='published'
                       HSET faq:cache:<hash> { answer, related_unit_id, unit_updated_at }
                       （Redis 缓存 key = sha1(question.lower().strip())；
                         unit_updated_at 取自 knowledge_units.updated_at 用于失效校验）
        │
        ▼
[用户提问] 命中缓存 + 单元版本未变 → 直接流式输出标准答案（跳过 LLM）
[        ] 命中缓存但 unit_updated_at 已变 → 删除缓存条目走主流程
```

### 5.4 知识缺口识别

```
[每次 AI 问答 record_log 节点]
        │
        ▼ 触发缺口识别
[gap_detector]
  top1_score = recalled_units[0].score if any else 0
  top3_avg = mean(recalled_units[:3].score) if len>=3 else 0
        │
        ▼ 当 top1<0.5 且 top3_avg<0.55
[INSERT knowledge_gaps]
  ON DUPLICATE KEY UPDATE ask_count = ask_count + 1, last_asked_at = NOW()
        │
        ▼ 缺口聚合（按 question_pattern 余弦相似度聚类）
[知识管理员] 缺口列表 → 一键创建关联 knowledge_unit
```

### 5.5 数据看板统计

```
GET /api/v1/dashboard/metrics
  └─ SELECT COUNT(*), COUNT(DISTINCT user_id), SUM(total_tokens), AVG(response_time_ms)
     FROM qa_access_logs WHERE created_at > NOW() - INTERVAL ? DAY

GET /api/v1/dashboard/rankings/questions
  └─ SELECT question, COUNT(*) AS c FROM qa_access_logs
     GROUP BY question ORDER BY c DESC LIMIT 20

GET /api/v1/dashboard/rankings/units
  └─ JSON_TABLE(recalled_unit_ids_json) → 聚合 → JOIN knowledge_units → 排序

GET /api/v1/dashboard/stats/tokens
  └─ DATE(created_at) 分桶 → SUM(total_tokens), AVG(response_time_ms)
```

无独立指标服务，直接走 MySQL 聚合查询。Q10 已确认不开 Prometheus/Grafana。

## 9. 工程规范

来自 [`build-fastapi-agent-projects`](../../.claude/skills/build-fastapi-agent-projects) skill，所有 kb_mp 代码必须遵守。

### 9.1 命名

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 文件 / 包 | snake_case | `knowledge_unit_repository.py` |
| 类 / Schema | PascalCase | `KnowledgeUnit`, `CheckPermissionsRequest` |
| 函数 / 变量 | snake_case | `check_permissions`, `recalled_units` |
| 常量 | UPPER_SNAKE_CASE | `FAQ_SIMILARITY_THRESHOLD` |
| Router | `<resource>_router.py` | `knowledge_router.py` |
| LangGraph 节点 ID | snake_case | `permission_filter` |
| HTTP 路径 | 复数名词 + 连字符 | `/api/v1/knowledge-units` |

### 9.2 目录与导入

- `__init__.py` 默认空白 / 仅文档字符串
- 导入顺序：标准库 → 第三方 → 项目内，由 Ruff 自动排序
- 禁止 `import *`
- 模块导入时不建网络连接（连接放 lifespan）

### 9.3 Schema 与注释

- HTTP / LLM 输出用 Pydantic v2 BaseModel
- 领域内部优先 `TypedDict` 或 `@dataclass(slots=True)`
- Docstring 只解释"为什么"，不逐行翻译

### 9.4 错误处理

- 业务异常抛 `AppError` 子类，全局 handler 映射 HTTP
- 第三方调用：4xx（429 除外）快速失败；网络/超时类可重试
- 不吞异常返回 None

### 9.5 必跑门禁（提交前）

```bash
uv run ruff format --check .
uv run ruff check .
uv run pytest
```
