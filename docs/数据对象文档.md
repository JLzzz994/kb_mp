## 1. 总览

11 张表（PRD 10 张 + chat_sessions 新增 1 张），按业务域分组：

| 域 | 表 |
| --- | --- |
| 组织权限 | users / departments / roles / user_roles / role_permissions |
| 知识资产 | knowledge_units / unit_permissions |
| AI 问答 | qa_access_logs / chat_sessions |
| 知识沉淀 | faqs / knowledge_gaps |

**通用约定**：
- 主键统一 `BIGINT UNSIGNED AUTO_INCREMENT`
- 创建时间 `created_at DATETIME DEFAULT CURRENT_TIMESTAMP`
- 更新时间 `updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP`
- 软删除：仅 `users.status` / `faqs.status` / `knowledge_gaps.status` 等业务状态字段，不另设 `is_deleted`
- JSON 字段类型：`JSON`（MySQL 5.7+ 原生）

## 3. 知识资产域

### 3.1 knowledge_units

| 字段 | 类型 | 约束 | 备注 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK | |
| unit_code | VARCHAR(32) | NOT NULL, UNIQUE | 业务编号，如 `KU-202608-0001` |
| title | VARCHAR(255) | NOT NULL | |
| content | MEDIUMTEXT | NOT NULL | 切片正文（按段落切分后单片内容） |
| summary | VARCHAR(512) | NULL | 首段摘要 |
| category | VARCHAR(64) | NULL | 业务分类 |
| source_file_name | VARCHAR(255) | NULL | 原始文件名 |
| file_type | VARCHAR(16) | NULL | `pdf` / `docx` / `md` / `txt` |
| file_size | BIGINT UNSIGNED | NULL | 字节数 |
| **content_hash** | **CHAR(64)** | **NULL, UNIQUE** | **原文 SHA-256（hex）；导入时做幂等校验，重复内容拒绝入库** |
| status | VARCHAR(16) | NOT NULL, DEFAULT 'active' | `active` / `vector_pending` / `failed` |
| creator_id | BIGINT UNSIGNED | NOT NULL, FK→users.id | 创建人 |
| created_at | DATETIME | NOT NULL | |
| updated_at | DATETIME | NOT NULL | |

索引：`UNIQUE(unit_code)`、`UNIQUE(content_hash)`、`KEY idx_category(category)`、`KEY idx_status(status)`、`KEY idx_creator(creator_id)`、`FULLTEXT KEY ft_content(title, content) WITH PARSER ngram`（用于关键字二次召回）

**FULLTEXT 中文分词**：中文环境必须用 ngram parser（MySQL 内置），默认按 2 字切分。

**状态语义**：
- `active`：已入库并向量化完成
- `vector_pending`：入库完成但向量化失败待重试
- `failed`：解析失败，不参与检索

### 3.2 unit_permissions

| 字段 | 类型 | 约束 | 备注 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK | |
| unit_id | BIGINT UNSIGNED | NOT NULL, FK→knowledge_units.id ON DELETE CASCADE | |
| target_type | VARCHAR(16) | NOT NULL | `global` / `department` / `role` / `user` |
| target_id | BIGINT UNSIGNED | NULL | global 时为 NULL；其余为目标实体 id |
| created_at | DATETIME | NOT NULL | |

索引：`KEY idx_unit(unit_id)`、`KEY idx_target(target_type, target_id)`

`global` 行：`target_type='global', target_id=NULL`。一个 unit 只能有一条 global 行（应用层校验）。

**target_id 外键策略**（应用层强制校验）：
- `target_type='global'` → target_id 必须 NULL
- `target_type='department'` → target_id → departments.id（ON DELETE CASCADE）
- `target_type='role'` → target_id → roles.id（ON DELETE CASCADE）
- `target_type='user'` → target_id → users.id（ON DELETE CASCADE）

MySQL 8.0.16+ 可加 CHECK 约束：
```sql
ALTER TABLE unit_permissions ADD CONSTRAINT chk_target_consistency CHECK (
    (target_type = 'global' AND target_id IS NULL) OR
    (target_type = 'department' AND target_id IS NOT NULL) OR
    (target_type = 'role' AND target_id IS NOT NULL) OR
    (target_type = 'user' AND target_id IS NOT NULL)
);
```

**JSON 字段说明**：概要设计 Q9 决策，JSON 字段保留日志原貌方便排查，不预拆关联表。后续若分析需求增长可物化宽表。

**JSON 字段完整结构**：

`recalled_unit_ids_json`:
```json
[{"id": 123, "score": 0.82}, {"id": 456, "score": 0.71}]
```

`authorized_unit_ids_json`:
```json
[123, 456]
```

`unauthorized_unit_ids_json`:
```json
[789, 101]
```

（注意：后两个是简单 int 数组，不是对象数组，与 `recalled_unit_ids_json` 结构不一致——已在 IMPL-M4 §3 permission_filter 节点统一为对象数组。是否需要同步？建议：在 §4.1 注释"结构对齐需 M4 IMPL 同步调整"。）

### 4.2 chat_sessions（新增，Q8 决策 + 参考借鉴）

| 字段 | 类型 | 约束 | 备注 |
| --- | --- | --- | --- |
| id | VARCHAR(64) | PK | UUID，由调用方生成 |
| user_id | BIGINT UNSIGNED | NOT NULL, FK→users.id ON DELETE CASCADE | |
| title | VARCHAR(255) | NULL | 会话标题（首问摘要） |
| history_json | JSON | NOT NULL | 完整对话历史：`{"turns":[{"role":"user","content":"..."},{"role":"assistant","content":"...","citations":[...]}], "slots":{}, "pending_turn":null}` |
| created_at | DATETIME | NOT NULL | |
| updated_at | DATETIME | NOT NULL | |

索引：`KEY idx_user_updated(user_id, updated_at DESC)`

**`history_json` 内部结构**：
```json
{
  "turns": [
    {"role": "user",      "content": "...", "created_at": "..."},
    {"role": "assistant", "content": "...", "citations": [...], "created_at": "..."}
  ],
  "slots": {
    "confirmed_entities": {"unit_id": 42},
    "focused_object":     null
  },
  "pending_turn": null
}
```

- `slots`：问答过程中已确认的实体（用户引用的知识单元 / 主体），供后续追问续接
- `pending_turn`：当前未完成的一轮（鉴权失败挂起时记录草稿；`POST /api/v1/ai/chat/resume` 时续接）。完整 schema：

```json
{
  "question": "原问题",
  "reason": "no_recall" | "no_recall_with_permission" | "low_confidence",
  "recalled_unit_ids": [101, 102],
  "authorized_unit_ids": [],
  "created_at": "2026-08-19T15:30:00+08:00",
  "status": "pending" | "resumed" | "abandoned"
}
```

**生命周期**：
- 用户进入对话页 → 前端 `POST /api/v1/ai/sessions` 创建记录（id 客户端生成 UUID）
- 每轮问答结束 → `PATCH /api/v1/ai/sessions/{id}` 更新 `history_json` 与 `updated_at`
- 鉴权失败 / 召回为空触发 interrupt → 写 `pending_turn`，等待用户重述
- 不做 TTL，由用户主动删除或前端"清空对话"按钮触发 `DELETE`

**Redis 缓存同步**（含版本失效校验）：
- 发布（status='published'）时 `HSET faq:cache:<question_hash> {answer, related_unit_id, unit_updated_at}`
- 驳回或下线时 `DEL faq:cache:<question_hash>`
- `faq_cache_lookup` 节点命中缓存时：若 `knowledge_units[related_unit_id].updated_at != cached.unit_updated_at` → `DEL` 缓存条目并走主流程

### 5.2 knowledge_gaps

| 字段 | 类型 | 约束 | 备注 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK | |
| question_pattern | VARCHAR(255) | NOT NULL | 模式化的问题（聚类代表） |
| question_pattern_hash | CHAR(40) | NOT NULL, UNIQUE | `SHA1(question_pattern.lower().strip())` |
| sample_questions_json | JSON | NOT NULL | 样例问题数组：`["问1", "问2", ...]` |
| ask_count | INT UNSIGNED | NOT NULL, DEFAULT 1 | 累计提问次数 |
| last_asked_at | DATETIME | NOT NULL | |
| status | VARCHAR(16) | NOT NULL, DEFAULT 'unresolved' | `unresolved` / `resolved` / `ignored` |
| resolved_unit_id | BIGINT UNSIGNED | NULL, FK→knowledge_units.id | 一键创建后回填 |
| created_at | DATETIME | NOT NULL | |
| updated_at | DATETIME | NOT NULL | |

索引：`UNIQUE(question_pattern_hash)`、`KEY idx_status(status)`、`KEY idx_last_asked(last_asked_at)`、`KEY idx_resolved_unit(resolved_unit_id)`（一键建档后回查）

**聚合逻辑**：
- 每次 `gap_detector` 检测到缺失 → `INSERT ... ON DUPLICATE KEY UPDATE ask_count = ask_count + 1, last_asked_at = NOW(), sample_questions_json = JSON_ARRAY_APPEND(..., '$', new_question)`
- 当 `JSON_LENGTH(sample_questions_json)` > 20 时裁剪前段

**裁剪算法**：当 `JSON_LENGTH(sample_questions_json) > 20` 时保留最近 20 条（按插入顺序）。
```sql
-- 在 MySQL 8 中可用 JSON_TABLE 重写：
UPDATE knowledge_gaps kg
JOIN (
    SELECT id, JSON_ARRAYAGG(q) AS trimmed
    FROM (
        SELECT kg2.id, JSON_UNQUOTE(JSON_EXTRACT(kg2.sample_questions_json, CONCAT('$[', idx, ']'))) AS q, idx
        FROM knowledge_gaps kg2
        CROSS JOIN JSON_TABLE(
            JSON_KEYS(kg2.sample_questions_json),
            '$[*]' COLUMNS (idx FOR ORDINALITY)
        ) AS jt
        WHERE kg2.id = :gap_id
        ORDER BY idx DESC
        LIMIT 20
    ) AS t
    GROUP BY id
) AS s ON kg.id = s.id
SET kg.sample_questions_json = s.trimmed
WHERE kg.id = :gap_id;
```

## 7. 索引与查询模式

| 查询 | 索引 |
| --- | --- |
| 登录：`WHERE username = ?` | `UNIQUE(username)` |
| 用户列表按部门：`WHERE department_id = ?` | `idx_department` |
| 角色权限校验：`WHERE role_id IN (?, ?, ?) AND permission_code = ?` | `uk_role_perm` |
| 知识单元分页查询：`WHERE category = ? AND status = ?` + `LIMIT ?, ?` | `idx_category`, `idx_status` |
| 关键字二次召回：`MATCH(title, content) AGAINST (?)` | `FULLTEXT ft_content` |
| 鉴权过滤拉权限：`WHERE target_type = ? AND target_id IN (?)` | `idx_target` |
| 看板访问量：`WHERE created_at > ?` | `idx_created` |
| FAQ 命中排行：`WHERE source = 'faq_cache' GROUP BY related_unit_id` | `idx_source_unit` |
| 用户会话列表：`WHERE user_id = ? ORDER BY updated_at DESC` | `idx_user_updated` |

### 9.3 时间字段

- 业务时间一律 `DATETIME`（避免时区混乱），应用层按 UTC 存储
- 数据库服务器时区设为 `+08:00`，写入时转换

### 9.4 与 Milvus 关系

`knowledge_units.id` 与 Milvus 中的 `unit_id`（INT64）一一对应。
导入时序：
1. `INSERT knowledge_units` 拿到 `id`
2. `BackgroundTasks.add_task(milvus_upsert, [(id, embedding_vector), ...])`
3. 失败时 `UPDATE status='vector_pending'`，后台重试

Milvus Collection schema：

| 字段 | 类型 | 备注 |
| --- | --- | --- |
| id | INT64 | PK，自增 |
| unit_id | INT64 | 与 MySQL `knowledge_units.id` 对应 |
| title | VARCHAR | |
| content | VARCHAR | 切片正文（Milvus VARCHAR 上限 65535） |
| embedding | FLOAT_VECTOR[1536] | text-embedding-3-small 输出维度 |
| category | VARCHAR | 检索后过滤用 |
| created_at | INT64 | 时间戳 |
