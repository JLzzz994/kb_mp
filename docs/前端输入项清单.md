# 前端输入项清单

| 项目 | 内容 |
| --- | --- |
| 文档版本 | V1.0 |
| 编写日期 | 2026-08-19 |
| 依据 | 《接口约定文档》《数据对象文档》《原型设计说明》M1–M6 specs |
| 用途 | 前端实现时表单/筛选/请求输入项的统一对照表 |

> 原则：后端 Pydantic 已锁定校验规则（长度、正则、枚举），前端做同构校验，避免依赖 422 兜底。

## 1. 全局输入（贯穿所有页面）

| 输入项 | 来源 / 约束 | 用途 |
| --- | --- | --- |
| `Authorization: Bearer <token>` | 登录响应 `access_token`，存 localStorage（演示期），axios 拦截器自动注入；JWT 8h 过期；401 拦截器清 token 跳登录 | 全部业务接口 |
| `permissions: list[str]` | 登录响应返回 17 权限码子集 | 菜单 + 按钮级权限渲染 |
| `X-Request-Id` | 客户端生成 UUID，可选 | 链路追踪 |
| 分页 `page` / `page_size` | `page ≥ 1`，`1 ≤ page_size ≤ 100` | 所有列表页 |
| 排序 `sort` | 形如 `-created_at`（前缀 `-` 倒序） | 列表页 |
| 文件上传头 | `Content-Type: multipart/form-data`，字段名 `files` | 知识导入 |

| --- | --- |

### 4.2 知识单元列表筛选（query）

| 参数 | 说明 |
| --- | --- |
| `keyword` | 标题关键字 |
| `category` | 业务分类 |
| `status` | active / vector_pending / failed |
| `page` / `page_size` / `sort` | 通用分页排序 |

### 4.3 知识单元编辑（PATCH `/knowledge-units/{id}`）

| 字段 | 校验 |
| --- | --- |
| `title` | 1–255 |
| `content` | 必填时非空 |
| `summary` | ≤ 512 |
| `category` | 可空 |
| `tags` | `list[str]`，可空 |

### 4.4 批量删除（DELETE `/knowledge-units`）

| 字段 | 校验 | 备注 |
| --- | --- | --- |
| `ids` | 1–100（接口约定文档）/ 1–200（M3 spec）——**文档间矛盾，前端建议按更严的 100 控制** | 部分失败返回 207，需逐条展示 |

### 4.5 四维数据权限配置（POST `/knowledge-units/{id}/permissions`）

| 字段 | 控件 | 约束 |
| --- | --- | --- |
| `permissions[].target_type` | global / department / role / user 四分区 | global 时 `target_id` 必须为 null，且一个 unit 最多一条 global（重复提交 409 `permission_conflict`） |
| `permissions[].target_id` | 部门树 / 角色列表 / 用户选择 | 非 global 时必为正整数 |
| `permissions` 整体 | — | 至少 1 条；保存前展示可读权限摘要（OR 规则 + 默认拒绝说明） |

### 4.6 鉴权调试（POST `/knowledge/check-permissions`）

| 字段 | 校验 |
| --- | --- |
| `user_id` | 正整数 |
| `unit_ids` | 1–500 |

## 5. M4 AI 对话工作台

| 输入 | 校验 / 说明 |
| --- | --- |
| 会话 `id` | **前端生成 UUID**（POST `/ai/sessions`） |
| `title`（创建/更新） | 可空，首问摘要 |
| 提问 `question`（`/ai/chat/stream`） | 1–2000，必填 |
| 续接 `question`（`/ai/chat/resume`） | 1–2000；interrupt 后保留输入框，用户补充提问触发；客户端无需区分 stream / resume |

### 5.1 SSE 事件输入（fetch + ReadableStream 解析）

| 事件 | 前端处理 |
| --- | --- |
| `ready` | 记录 session_id，进入生成态 |
| `progress` | 阶段进度条（可选展示） |
| `delta` | 流式追加文本 |
| `citation` | 右侧引用列表（unit_id / title / score） |
| `unauthorized` | 无权限单元提示：只展示标题，不泄露正文，附"申请权限"入口 |
| `interrupt` | 展示"未找到相关知识"，保留输入框引导补充 |
| `final` | 收尾：answer + usage（prompt/completion/total_tokens、response_time_ms）；FAQ 缓存命中标记"标准答案 · 缓存命中" |
| `error` | SSE 内错误码：llm_timeout / llm_unavailable / vector_unavailable / recall_empty_unexpected / prompt_assembly_failed（与 HTTP 错误码隔离） |

## 8. 待确认 / 风险项

1. **批量删除 ids 上限矛盾**：接口约定文档 §7.3 写 1–100，M3 spec `BatchDeleteRequest` 写 `max_length=200`。建议前端按 100 控制，并推动后端统一。
2. **错误态必须保留用户输入**：仅高亮错误字段，绝不清空（原型设计说明 §5 通用状态规则）。
3. **破坏性操作二次确认**：删除、驳回、停用统一弹确认框。
4. **表单校验来源**：可用 `openapi.json`（始终暴露）+ `openapi-typescript-codegen` 生成 TS 类型，避免手写 schema 漂移。
