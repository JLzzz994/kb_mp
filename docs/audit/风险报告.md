## 2. CRITICAL 级（8 条，必须修复）

按修复优先级排序：

### C1. Redis Key 漂移——权限失效链路断裂（IMPL vs Spec）
- **位置**：`IMPL-M3 §6 load_user_permission_bitmap` 用 `knowledge:bitmap:{user_id}`；Spec M3 §5.6 + M1 §8 + M2 §5.2 + 概要设计 §6 均为 `auth:bitmap:{user_id}`
- **影响**：M2 `RoleService.assign_permissions` 调用 `DEL auth:bitmap:*` 无法命中 `knowledge:bitmap:*`，权限变更后用户最长 5 分钟仍可越权访问
- **修复**：IMPL-M3 §6 全文替换 `knowledge:bitmap:` → `auth:bitmap:`

### C2. M3 Repository 缺 6 个方法——M4/M6 调用全部 AttributeError（IMPL vs Spec）
- **位置**：`IMPL-M3 §5/§6 KnowledgeUnitRepository`；M4 §3/§4 与 M6 §2/§5 依赖
- **缺失方法**：`get_updated_at` / `get_status` / `get_title` / `list_content_for_ids` / `list_permissions_for_units` / `list_faqs_by_related_unit_ids`
- **影响**：照写 IMPL-M4 / IMPL-M6 必然 AttributeError，LangGraph 工作流无法启动
- **修复**：IMPL-M3 §5/§6 增补上述 6 个方法

### C3. M3 缺 `KnowledgeUnitService.create()`——M6 一键建档阻断（IMPL vs Spec）
- **位置**：IMPL-M3 §5 仅 list/get/patch/batch_delete；M6 §5 `one_click_create_unit` 第 392 行调用
- **影响**：知识缺口→单元的建档闭环断；`KnowledgeUnitCreate` Schema 也未定义
- **修复**：IMPL-M3 §5 增 create() 方法 + §4.2 Schema

### C4. LangGraph 节点签名不一致（IMPL vs Spec）
- **位置**：IMPL-M4 §3 节点 `(state, runtime: Runtime[GraphContext])`；Spec M4 §5.5 为 `(state, ctx)`
- **影响**：照写后 mock 与测试用 Runtime 而非 ctx，与 Spec §10 测试用例不符
- **修复**：二选一统一（���荐保留 Runtime，修订 Spec）

### C5. 接口路径前缀漂移（接口约定 vs PRD/需求）
- **位置**：PRD §6 与需求 §2.9.8 全表写 `/api/...`；接口约定 §1 全部为 `/api/v1/...`
- **影响**：前端按 PRD 实现找不到全部接口
- **修复**：PRD §6 + 需求 §2.9.8 加 `/v1` 前缀；新增 ADR-0007 锁定

### C6. knowledge-units 路径风格漂移（接口约定 vs PRD/需求）
- **位置**：PRD §6 `/api/knowledge/units`（嵌套单数）；接口约定 §7.3 `/api/v1/knowledge-units`（连字符复数），覆盖 5 条路径
- **影响**：接口约定文档与 PRD/需求全部不对齐
- **修复**：同步 PRD §6 与需求 §2.9.8

### C7. LangGraph 节点数自相矛盾（概要设计内部）
- **位置**：概要设计 §5.2 标题=7、节点表=8（含 interrupt）、§6 决策表=7、§10 P2=6、ADR-0002=6
- **影响**：P2 实施期 State 字段 / checkpoint 边界 / SSE 事件归属反复返工
- **修复**：以节点表 8 为准，全文统一

### C8. M4 依赖方向错误（Spec 内部）
- **位置**：M4 §1 把 M5（数据看板）列为依赖模块；README §1.1 标 M4 上游仅 M1/M3
- **影响**：依赖图反转；评审与实现脱节
- **修复**：M4 §1 删除 M5 依赖；若 M4 启动确实需 M5 运行时单独标注

## 14. 最终结论与建议

**文档集整体覆盖率 95% 以上**，但跨文档一致性存在：

| 等级 | 数量 | 性质 |
| --- | --- | --- |
| critical | **10** | **必须 0 容忍进入编码** |
| high | **33** | **必须 P1 前清零** |
| medium | 67 | 编码时按周消化 |
| low | 53 | 留作 v1.1 修订 |

### 14.1 紧急行动清单（按 P0 阶段阻断项）

1. **架构图**：拆"看板·沉淀·FAQ"合并盒 → 3 个独立服务；新增第 5 层"质量属性"
2. **原型**：知识缺口预览改为问题模板样式（不用上传队列样式）；补 4 种 SSE 状态截图；补三角色侧栏对比
3. **文档对齐**：PRD/需求统一加 `/v1` 前缀 + `knowledge-units` 风格 + `PATCH` 方法（出 ADR-0007）
4. **IMPL 修复**：C1 Redis Key `knowledge:bitmap:` → `auth:bitmap:`；C2 M3 Repository 补 6 个方法；C3 M3 增 `create()`；H14 pyproject.toml 补 11 依赖
5. **LangGraph 节点签名 + 节点数**：统一 Runtime 注入 + 8 节点（faq_cache_lookup / retrieve / rerank / permission_filter / interrupt / assemble_prompt / generate / record_log）

### 14.2 编码启动门禁

完成上述 5 项后：
1. 重跑 Agent 1 + Agent 6（路径风格 + IMPL 可执行性）
2. 跑 ruff format + ruff check + pytest 三件套
3. 冻结文档 V1.0 基线，进入 P0 编码

### 14.3 演示阶段需补的预览图（按重要性）

- **必须补**：登录、个人中心、用户管理、角色权限、部门管理、知识单元列表、已发布 FAQ（7 张桌面）
- **必须补**：对应 7 张移动端
- **必须补**：4 张 SSE 状态（delta/final/error/interrupt）
- **必须补**：3 张角色侧栏对比（系统管理员/知识管理员/普通用户）
- **建议补**：2 张破坏性操作二次确认弹窗 + 1 张 FAQ 审核编辑弹窗

**结论**：kb_mp 项目文档完整性已达标，但跨文档一致性存在 10 条 critical + 33 条 high 阻塞项，**必须先做一轮集中修复（含架构图与原型）再进入编码阶段**，否则 P2 起会连环返工。
